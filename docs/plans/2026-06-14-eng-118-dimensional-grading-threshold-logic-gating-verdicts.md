# Plan — Dimensional grading: threshold logic gating verdicts (ENG-118)

## Anti-anchoring check

- **Problem (operator-perspective):** "The qa and review agents self-grade dimensional scores (ENG-117 / ENG-119), self-emit `verdict pass`, and the issue advances. The orchestrator has no enforcement against evaluator bias — an agent that grades `coverage=0.65` and self-PASSes ships sub-floor work silently. Calibration (ENG-39) cannot exist without a deterministic record of `agent claimed X vs orchestrator enforced floor Y`."
- **Brainstorm framing:** matches the problem one-for-one. The fix is two new orchestrator-side post-dispatch detectives (`_validate_review_thresholds`, `_validate_qa_thresholds`) in `bin/run-stage.sh` that read the per-dispatch payload, compare each dimension's `score` to operator-configured floors in `.review.thresholds.*` / `.qa.thresholds.*`, and — on sub-threshold AND agent-self-PASS — post a coerced `verdict fail --target implementing --reason dimensional-threshold-not-met` Linear comment. The orchestrator's coerced fail-marker wins on `createdAt` within the same dispatch_id; `verdict_handler`'s existing `pipeline-rejection` branch routes the loopback unchanged. **No `verdict_handler` code changes; no new schema; no agent-side prompt changes other than removing two pointer-sentences.**
- **Proportionality:** ~120 added lines in `bin/run-stage.sh` (two functions sized to mirror `_validate_review_payload`); ~7 added lines in `bin/pipeline-events.json` (one top-level `fail_reasons` array, one `field_registry_by_arm.fail.reason` mapping, one `metric_names` token); ~250 added lines of fixture-driven tests in `bin/run-stage-test.sh`; ~20 added lines in `bin/vocabulary-cleanliness-test.sh`; ~80 added lines in `docs/configuration.md`; one new section in `docs/runbooks/recovery.md`; one new row in `CLAUDE.md` failure-mode table. Six-line trim in `AGENT_PROMPTS.md`. Mirrors three established precedents: ENG-117/ENG-119 payload-detective shape, ENG-190 ledger-detective shape, ENG-191 `pass_reasons` per-arm registry override. Subsystem count = 3 load-bearing (orchestrator + Linear-contract/config + tests) plus prompt/docs subordinate. Within the autonomy-safe rubric. Proceed.

## Goal

When a reviewing-stage agent emits `verdict approve` AND any payload-emitted dimension's `score` is below its `.review.thresholds.<dim>` floor (enum `fail<concern<pass`), OR a qa-stage agent emits `verdict pass` AND any payload-emitted dimension's `score` is below its `.qa.thresholds.<dim>` floor (number in `[0.0, 1.0]`), the orchestrator's new post-dispatch detective (`_validate_review_thresholds` / `_validate_qa_thresholds`, slotted AFTER the existing payload + ledger validators and the ENG-191 deferred-majors hook, BEFORE `push_branch_if_ahead`) posts a coerced `verdict fail --target implementing --reason dimensional-threshold-not-met` Linear comment via `bash bin/pipeline.sh event` (closed-vocabulary `dimensional-threshold-not-met` in `fail_reasons` per `field_registry_by_arm.fail.reason`); the orchestrator's fresh fail-marker wins `find_fresh_verdict`'s strict-id-match path (latest `createdAt` within current `PIPELINE_DISPATCH_ID`) and `verdict_handler`'s existing `pipeline-rejection` branch loops the issue back to `stage:implementing` unchanged. A sibling structured Linear comment under `--sig dimensional-threshold/<stage>/<ident>` enumerates the failed dimensions (name, score, threshold, miss-reason ∈ `{below-threshold, missing-in-payload}`); a `dimensional_threshold_coerced` metric event lands in `events.jsonl`. The agent's self-reported `threshold_met` (qa) / `thresholds_met[]` (review) fields are read-only forensic surfaces (orchestrator never consults them for gating — disagreement is the calibration substrate ENG-39 consumes). Both threshold blocks are OPTIONAL — absent block → pre-ENG-118 behaviour preserved (gate no-op). Composes with shipped ENG-190 (critical-floor halt runs FIRST; threshold gate never runs when the ledger halts) and shipped ENG-191 (deferred-majors enumeration posts AT step 3 of the post-dispatch sequence, threshold gate at step 4 of the same sequence — operator controls whether the deferred-majors selective exit composes through to qa via `review.thresholds.correctness ∈ {concern,fail}` vs coerces back to implementing via `review.thresholds.correctness == pass`).
